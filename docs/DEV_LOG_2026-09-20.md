## 1. C6 — loop invariant（單調 while 模板）

**設計定案**（唔做 unroll 硬爆）：LLBC `Loop` block 認形——

- 頭部＝loop-carried 重讀（Copy）＋單一比較條件（Lt/Le/Gt/Ge）
- 內嵌 bool Switch：以尾語句定性臂（`Continue` 結尾＝body、空／`Break` 結尾＝出口）；實證兩形（false→出口 fall-through／false→Break）全支援
- 條件極性驗證（body 必須喺 cond 真時執行）；出口臂白名單（Storage*/Nop＋可選 Break）
- 步進認形：temp-Copy 兩段式（`t := i ± c; i := t`）或 checked tuple `t.0` 投影直寫；步進容許 `AddChecked`（溢出語義由模擬承擔）
- 模板外一律如實降級（reason 指明「invariant 推唔出」等）

**模擬**＝迭代執行（語義模擬，唔係編碼 unroll）：步數上限由初值/界推導，
`LOOP_ITERS_HARD_CAP=4096` 硬上限防大界值 DoS（n=10¹⁵ 唔會實際跑到底）。

**編碼**＝witness 統一尾段恆等化：見證模式早 return、逐槽 `{x=v}` 單點域＋
直接求值；直線 eq 喺 loop 多重賦值下唔成立；zero-iteration 死槽域清空。
直線模式完全不變（C2/C3 口徑零改動）。

**前置**：charon `--no-dedup-serialized-ast` fallback 入 `c0_spike.py`——
LLBC 根冇 dedup 解表、Deduplicated 常數不可猜（鐵律）。CI 實證 runner charon
支援 flag，**m0 全部真檔零 Deduplicated**。隨之暴露 `Const = {Untagged:
[literal, ty]}` no-dedup 常數形態，`parse_const` 已支援（新舊兩形單元測試覆蓋）。

## 5. Soundness 洞修復（C7 揭露之既有缺陷）

1. **fallback guard 無條件放行**：`Some(_) if path.fallback => {}` 連 base
   值都收——fact(100000) 遞迴路徑撞深限後 fallback path 誤認證 ret=1。
   修：`PirPath.excl`（分流常數表），fallback guard 要求 scrutinee ∉ branch 常數。
2. **模擬錯誤優先級**：Ok 臂 guard 失敗曾無條件覆寫 last 錯誤，掩蓋真因。
   修：Overflow 恆最優先、Reason 保留首個（path 序最接近真實執行路徑）。

修後 CLI 實測：fact(100)/fact(100000) 均如實 UNKNOWN（溢出排除／深度超限
4096），唔再有誤認證。
